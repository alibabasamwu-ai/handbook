alibaba-product-health-check

阿里巴巴国际站商品健康度诊断技能。通过浏览器会话依次访问商品管理、商品运营工作台、数据参谋、行业征品等后台页面，采集产品赛道结构、主营占比、分组排序、产品分层、零效果产品、违规问题等6大维度数据，输出结构化Word诊断报告并保存到桌面。适用于所有阿里国际站店铺（不限行业）。触发关键词：商品健康度、产品健康度、店铺产品体检、健康度诊断、店铺产品盘点、产品结构分析。

阿里国际站商品健康度诊断 SKILL

概述

通过浏览器会话自动访问阿里巴巴国际站卖家后台，抓取商品健康度关键指标数据，基于行业标准和最优实践生成诊断报告。适用于所有类目店铺。

执行流程

Step 1: 收集用户输入
  │  确认主营类目、店铺行业、报告输出偏好
  │  ↓
Step 2: 检查登录状态
  │  访问 i.alibaba.com，判断是否需要登录
  │  ↓
Step 2.5: 自动抓取店铺真实名称（必须执行）
  │  浏览器访问后台获取公司英文名 + 阿里主页链接
  │  用于报告封面，替代账号邮箱
  │  ↓
Step 3: 数据采集（6大数据源，浏览器分步抓取）
  │  3.1 商品管理页 → 赛道结构、违规问题
  │  3.2 商品运营工作台 → 产品分层
  │  3.3 数据参谋零效果 → 沉睡产品清单
  │  3.4 商品管理页按类目筛选 → 主营产品占比

  │  3.6 行业定向征品 → 征品机会
  │  ↓
Step 4: 行业赛道比例研究（AI辅助分析）
  │  基于用户声明的行业与产品线，给出交易品/商机品最优比例建议
  │  ↓
Step 5: 生成Word诊断报告
  │  按6章节结构输出，保存到桌面
  │  ↓
Step 6: 呈现结果 + 关键结论摘要

Step 1: 收集用户输入

执行前必须向用户确认以下3个信息（不确认则不能生成准确报告）：

信息项 说明 示例
主营类目 用户声明的核心产品线（用于计算主营占比） "安全帽 + 反光服 + 安全绳"、"USB充电器 + 数据线"、"宠物推车 + 宠物玩具"
店铺行业 用于AI推算行业赛道比例建议 "PPE个人防护"、"3C电子配件"、"宠物用品"
报告文件名 输出的Word文件名（默认：商品健康度诊断报告_日期.docx） 用户可自定义

询问模板：

在开始检查前，请确认以下3个信息：

1. 你的主营类目是什么？（用于计算主营占比，请写清楚2-4个核心产品线）
2. 你的店铺属于哪个行业？（我会基于行业特性给出赛道比例建议）
3. 报告文件名希望自定义吗？（默认：商品健康度诊断报告_YYYYMMDD.docx）

判断规则： 如果用户回复中已经包含以上信息（比如首轮请求就说"我是做安全帽的店铺"），直接使用无需重复问；缺失才追问。

Step 2: 检查登录状态

访问 https://i.alibaba.com/prod/product_manage#/product/online：

  • 页面跳转到 login.alibaba.com → 未登录，提示用户完成登录后重试
  • 正常显示商品管理页 → 已登录，继续

Step 2.5: 自动抓取店铺真实名称（必须执行）

目的： 报告封面使用真实公司名称，而非账号邮箱，适配多商家/多店铺场景。

执行方式： 浏览器访问阿里国际站卖家后台，从以下任一位置读取：

来源 操作
后台顶部导航栏 通常显示公司名称或店铺名
公司信息页 访问 https://i.alibaba.com/company/company_info.htm
店铺前台链接 格式为 xxxx.en.alibaba.com，从后台"我的店铺"或地址栏获取

需记录字段：

字段 说明 用途
company_name_en 公司英文注册名称 报告封面"店铺名称"
store_url 阿里主页链接（xxxx.en.alibaba.com） 报告封面"主页链接"
company_name_cn 公司中文名称（如有） 可选，报告备注

如无法自动读取（页面超时/结构异常）：
- 降级方案：使用用户提供的账号邮箱作为店铺标识，在报告中注明"（账号邮箱）"
- 不允许凭猜测填写公司名称

报告封面写法：

店铺名称：Hangzhou XXX Co., Ltd
主页链接：xxxx.en.alibaba.com

Step 3: 数据采集（关键 · 分步执行）

重要原则：
1. 每次抓取只做一件事（浏览器session超时限制严格，一次任务超过5-8步大概率超时）
2. 每次抓取必须截图确认（数字读错代价大）
3. 优先看页面显示的数字，其次才是JS console抓取
4. 不要用querySelectorAll('tr')数产品行（会把嵌套子行也数进去）

3.1 商品管理页 - 赛道结构 + 违规问题

入口： https://i.alibaba.com/prod/product_manage#/product/online

依次执行5次筛选搜索，每次记录页面右下角"总数"：

搜索序号 筛选条件 记录字段
① 商品上下架状态=已上架（公共产品） 已上架总数
② ①的基础 + 商品类型=交易品 交易品数
③ ①的基础 + 商品类型=商机品 商机品数
④ ①的基础 + 商品质量分=0~3.9 低分品数
⑤ ①的基础 + 是否有违规问题=是 已上架违规数

关键提示：
- 页面元素引用（refs）会随刷新失效，遇到 Element not found 立即重新snapshot
- 总数位置：列表右下角，格式"总数: XXXX"
- 每次修改筛选条件后要等5秒让数据加载

3.2 商品运营工作台 - 产品分层

入口： https://hz-productposting.alibaba.com/product_operate/product_growth.htm

页面直接显示以下数字，用JS或直接读页面文本抓取：

// 抓取产品分层数据
const levels = {};
document.querySelectorAll('[class*="level-item"], [class*="tier"], .product-level').forEach(el => {
  const text = el.innerText;
  const match = text.match(/(低质品|普通品|潜力优品|优品|爆品)[（(](\d+)[)）]/);
  if (match) levels[match[1]] = parseInt(match[2]);
});
console.log(JSON.stringify(levels));

需记录字段： 低质品数 / 普通品数 / 潜力优品数 / 优品数 / 爆品数 / 右上角"重铺诊断"数

3.3 数据参谋零效果产品 【专项优化 v2.0】

入口： https://data.alibaba.com/product/overview

⚠️ 铁律：每页固定10条产品，永不变动。任何显示其他数字（如40条）都是取数方式错了，不是页面变了。

❌ 已知3大取数陷阱（严禁使用，血泪教训）：

错误方法 会得到的错误结果 错误原因
保留默认勾选的"橱窗产品" 数字异常少（如1款） 该过滤器只保留橱窗产品，会屏蔽95%以上数据
document.querySelectorAll('tr').length 数字虚高4倍（如40/页） tr包含表头行、展开的子行、操作行等非产品行
读 window.MYDATA_DATA.ineffTotal 数字不可控（如1605） 该字段不对应零效果产品总数，是其他业务数据

✅ 标准取数流程（固化，不可变）：

🎯 检查逻辑（统一口径）：

指标 定义 达标标准
零效果产品占比 ≥90天无效果产品数量 ÷ 已上架总数 × 100% < 5%

为什么统一用90天：
- 90天是阿里国际站官方公认的产品沉睡分界线
- 不区分赛道可以简化诊断逻辑，避免商机品/交易品数据无法精确拆分带来的偏差
- 单一指标便于历史对比和目标追踪

标准取数步骤（一次抓取即可）：

Step 1: 访问 https://data.alibaba.com/product/overview
Step 2: 等待8秒页面加载
Step 3: 点击顶部"零效果产品"Tab，等待5秒
Step 4: 【关键】检查"橱窗产品"复选框，如已勾选必须取消
Step 5: "无效时长"下拉框选择"大于等于90天"
Step 6: 点击"搜索"按钮，等待5秒
Step 7: 截图页面底部分页器（必须截图存证）
Step 8: 从分页器读取总页数 XX（格式："1/XX" 或 "共 XX 页"）
Step 9: 计算：零效果产品总数 = XX × 10

📐 计算规则（严格执行）：

基础计算：总页数与总数换算

场景 计算方式 示例
总页数 ≥ 2 总页数 × 10 = 总数 57页 × 10 = 570款
总页数 = 1 直接数当前页产品行数（可能<10条） 显示7条 = 7款
显示"无数据" 总数 = 0 达标

末页误差说明： 末页可能不足10条（如实际567款显示57页，末页7条），产生±10条内的误差属于合理范围，不影响诊断结论。

零效果占比计算：

计算项 公式 达标标准
零效果产品占比 ≥90天零效果总数 ÷ 已上架总数 × 100% < 5%

举例说明：

假设：已上架2380款
     ≥90天零效果产品显示57页

计算过程：
├── 零效果产品总数 = 57页 × 10条/页 = 570款
├── 零效果产品占比 = 570 ÷ 2380 = 23.9%
├── 警戒线：< 5%（对应 119款）
└── 状态：严重超标（超出警戒线约5倍）

🔍 抓取质量校验（每次必做）：

抓取完成后，立即执行以下2项校验：

  1. ✓ 截图校验： 分页器截图必须能清晰看到"1/XX"数字，否则重新截图
  2. ✓ 逻辑校验： 零效果总数 ≤ 已上架总数（如零效果>已上架，一定错了，需重抓）

任一校验不通过 → 立即从Step 1重跑，不允许带错误数据进入报告。

📝 报告中的数据表述规范：

【零效果产品检查】
零效果产品（≥90天）：XXX款
├── 数据来源：XX页 × 10条/页 = XXX款
├── 已上架总数：XXXX款（来自商品管理页）
├── 零效果占比：XX.X%（零效果数 ÷ 已上架总数）
├── 警戒线：< 5%（对应 XX 款）
└── 状态：[达标/超标X倍]

⚡ 效率优化建议：

  • 只需抓取一次（≥90天），耗时约1-2分钟
  • 如遇下拉框交互失败，直接用 browser_act 自然语言描述："在无效时长下拉框中选择大于等于90天，点击搜索按钮"
  • 分母使用3.1章节抓取的已上架总数

3.4 主营产品占比（按用户声明类目筛选）

入口： https://i.alibaba.com/prod/product_manage#/product/online

根据用户在Step 1声明的主营类目，逐个执行"商品所在类目"筛选：

  • 商品上下架状态=已上架
  • 商品所在类目=[主营类目1] → 记录数量
  • 清空 → 商品所在类目=[主营类目2] → 记录数量
  • 清空 → 商品所在类目=[主营类目3] → 记录数量

类目选择器提示：
- 弹出的类目树可能多级，逐级点击展开
- 若找不到精确类目，选择最接近的父类目并在报告中注明实际选择的类目名称

计算： 各主营类目数量之和 ÷ 已上架总数 = 主营占比

3.5 产品分组与排序

在商品管理页左侧或筛选区找到"商品分组"下拉框，读取所有分组名称的排序顺序（从上到下）。

若分组较多，至少记录前10-15个分组的：
- 分组名称
- 每组产品数
- 是否属于主营类目

3.6 行业定向征品（可选，用于P2建议）

入口： https://hz-productposting.alibaba.com/product/collect_product.htm

读取当前"交易品定招"和"商机品定招"下的：
- 全部商品数 / 待优化商品数 / 加速中商品数 / 加速完成商品数

用于报告中"P2 优化建议"的征品补量方向。

Step 4: 行业赛道比例研究

基于用户在Step 1声明的店铺行业和主营类目，输出交易品/商机品最优比例建议。

判断逻辑（内嵌行业知识）：

产品特征 建议交易品占比 定位
标准化极高、客单价低、决策周期短（如反光服、日用品、小家电配件） 60%~80% 引流款、RTS主力
标准化中等、客单价中、决策中等（如安全帽、宠物用品、家居） 40%~55% 平衡款
定制化强、客单价高、决策周期长（如安全绳、大件家具、工业设备） 20%~30% 商机主导

若用户提供的品类无法直接判断，通过 web_search 或AI推理给出比例建议，并在报告中注明"基于行业逻辑推算"。

综合店铺建议比例区间： 根据主营各产品线加权平均后给出（如45%~55%）。

Step 5: 生成Word诊断报告

使用 docx skill 生成报告，保存到桌面。

报告文件路径： /Users/[username]/Desktop/[用户指定文件名].docx

报告章节结构（固定）

封面
├── 报告标题：商品健康度诊断报告
├── 店铺名称（公司英文名）/ 主页链接 / 主营产品 / 检查日期
│   ※ 店铺名称来自 Step 2.5 自动抓取，优先用公司英文名；抓取失败则用账号邮箱
└── 综合健康评级（低风险/中风险/高风险，红黄绿三色）

第一章：产品赛道结构
├── 交易品 vs 商机品比例表
├── 行业建议比例表（按产品线拆分）
├── 诊断结论
└── 整改建议

第二章：主营产品占比 & 分组排序
├── 2.1 主营产品占比（各类目数量+合计+占比）
└── 2.2 产品分组排序检查（表格展示前10分组+评估）

第三章：问题产品检查
├── 3.1 低质品/低分品/违规品（三项归零标准）
└── 3.2 产品分层分布（爆品/优品/潜力优品/普通品/低质品）

第四章：零效果产品检查
├── 检查表（≥90天数量、占比、警戒线）
├── 根本原因分析
└── 整改方案

第五章：违规侵权检查
├── 已上架违规 / 已下架违规 / 商品雷达预警（三项归零）
├── 平台被动检测局限性说明
└── 持续监控路径

第六章：优先行动清单
└── P0/P1/P2 三级优先级 + 完成时限 + 操作路径直达

报告样式规范（去AI化 + 结构化）

样式项 规范
字体 Arial（正文22pt，标题26-32pt）
主题色 深蓝 #1A5276（品牌色）+ 深灰 #1A1A1A（正文）
状态色 达标绿 #1E8449 / 预警橙 #D35400 / 严重红 #C0392B
表格 浅蓝表头 #E8F0F7 + 灰色边框 #CCCCCC
页眉/页脚 页眉：报告标题+日期；页脚：页码"第X页/共Y页"
结论表述 直接给数字+判断+行动路径，禁用"通过分析可以看出"等空话

报告数据完整性要求

  • 每个数字必须有来源（页面/接口/用户声明）
  • 判断必须有标准（"标准≥80%"、"警戒线<5%"）
  • 建议必须有路径（"商品管理 → XXX → XXX"）
  • 时限必须有节点（"本周内"、"2周内"、"本月内"）

异常处理

异常场景 检测信号 处理方式
用户未登录 URL跳转到login.alibaba.com 提示用户完成登录后重试
类目选择器交互失败 多次点击下拉框无响应 让用户截图后台类目并手动告知数字
零效果页面"橱窗产品"被勾选 结果异常少（<10条但页码显示很多页） 提示先取消勾选"橱窗产品"
浏览器session超时 单次任务超过400秒 拆分为更小任务，用sessions_send继续
页面refs失效 Element "eXXX" not found 立即重新snapshot再点击
数字读取失败 页面无"总数"字样或读取NaN 截图上传，让用户核实

操作规范

  1. 数据准确性优先于速度：宁可多花时间核实数字，也不要把错误数据写入报告
  2. 每次抓取必须截图：截图是数字准确性的最后保障
  3. 不要伪造数据：任何一项数据无法确认时，报告中明确写"待人工核实"
  4. 保持中文输出：报告全部中文，专业术语可保留英文原文
  5. 不要跨店铺执行：一次运行只处理一个店铺，不要在同一次任务中混合多店铺数据

技能升级方向（未来可扩展）

这是一个专为阿里国际站店铺设计的商品健康度自动诊断工具。运行一次，即可获得完整的店铺产品健康度Word报告，覆盖6大核心维度，直接指出问题、给出整改路径。

序号检查维度检查内容

5零效果产品≥90天无曝光产品数量与占比（警戒线<5%）
6违规问题已上架/已下架违规产品数 + 商品雷达异常预警

  2. 报告包含6章节 + 优先行动清单，共约15-20页
  3. 所有数据带原始来源+行业标准对比+可直接落地的整改路径
  4. 对话中同步输出核心数据摘要和首要问题

3.2 完整执行流程（用户视角）

Step 1：Agent 询问你3个关键信息

触发技能后，Agent会先问你以下3件事（这些信息决定报告的准确性）：

  1. 主营类目是什么？（例如：安全帽 + 反光服 + 安全绳；或：USB充电器 + 数据线）
  2. 店铺属于哪个行业？（例如：PPE个人防护 / 3C电子配件 / 宠物用品）
  3. 报告文件名要自定义吗？（默认：商品健康度诊断报告_YYYYMMDD.docx）

💡 提示：如果你在触发语中已经说了"我是做安全帽的店铺"，Agent会跳过重复询问。

Step 2：Agent 自动打开后台采集数据

Agent会依次访问4个后台页面，你会看到浏览器窗口自动打开并翻页：

  1. 商品管理页 → 抓取赛道结构、违规数据
  2. 商品运营工作台 → 抓取产品分层
  3. 数据参谋零效果 → 抓取沉睡产品数据
  4. 商品分组排序 → 检查分组顺序

⏱️ 全程约需 8-15 分钟，取决于店铺产品数量。

Step 3：Agent 生成Word报告

数据采集完成后，Agent会自动生成一份完整的诊断报告，保存到桌面。

Step 4：Agent 输出结论摘要

对话中同步给出核心数据+首要问题+首要行动，无需打开Word也能快速了解店铺状态。

四、报告内容说明

每份报告固定6章结构，全部15-20页，直接可用于团队汇报或运营复盘。

章节内容核心用途
封面综合健康评级（低/中/高风险）一眼判断店铺整体状态
第一章产品赛道结构（交易品vs商机品）判断店铺是否偏科，是否需要补发某类产品
第二章主营占比 + 分组排序判断主营产品是否占主导，展示位是否合理
第三章低质品/低分品/产品分层找出需要下架、优化、升级的产品
第四章零效果产品清单找出沉睡产品，启动批量重发计划
第五章违规侵权检查确认合规状态，避免降权风险
第六章优先行动清单（P0/P1/P2）明确本周/2周/本月要做什么，附操作路径

六、常见问题与故障排除

Q1：Agent提示"需要登录"怎么办？

  • 直接在Chrome中打开 https://i.alibaba.com/ 完成登录，然后回到对话中告诉Agent"我登录好了，继续"即可。

Q2：零效果产品数量抓得不对（比如只显示1条但实际有几百条）

  • 原因：数据参谋零效果页面默认勾选了"橱窗产品"复选框，过滤了大部分数据。
  • 解决：技能已内置该场景检测，会自动取消勾选。如果仍有问题，请手动打开该页面确认勾选项状态并告知Agent。

Q3：主营类目筛选时找不到我的类目

  • 原因：阿里后台类目名称可能与你日常叫法不一样（比如你说"反光服"，后台叫"反光安全服"）。
  • 解决：Agent会尝试匹配相近类目，并在报告中注明实际选择的类目名称。你也可以提前告诉Agent"我的类目在后台叫XXX"。

Q4：报告中某项数据显示"待人工核实"

  • 原因：某个数据点在自动化过程中未能可靠抓取（比如页面交互失败）。
  • 解决：按报告中给出的"手动核查路径"人工补充数据。这是设计上的容错机制，不是错误。

Q5：浏览器session超时中断了怎么办？

  • 原因：单次浏览器任务超过约8分钟会强制中断。
  • 解决：Agent会自动拆分任务并续跑。你可以直接在对话中说"继续"，Agent会从中断处恢复。

Q6：报告数字与我手动核对的不一致

  • 原因：可能是页面数据缓存、时间点差异（如你8点看的是7点数据）或筛选条件不一致。
  • 解决：告诉Agent具体哪项数据不对，Agent会重新抓取核实。数据准确性优先，宁可多花时间也要保证正确。

产品特征建议交易品占比典型品类示例

八、能力边界与免责说明

8.1 本技能能做什么

  1. 自动抓取阿里国际站后台6大维度的公开数据
  2. 基于内置行业标准生成结构化Word诊断报告
  3. 给出可直接落地的P0/P1/P2三级行动清单
  4. 每次执行都是独立的（不依赖历史数据缓存）

8.2 本技能不做什么

  1. ❌ 不主动修改后台任何数据（只读诊断，不执行操作）
  2. ❌ 不做主动侵权风险扫描（如图片logo识别、商标词库比对）
  3. ❌ 不做外观专利/发明专利查询
  4. ❌ 不做视频内容侵权分析
  5. ❌ 不做P4P直通车数据关联分析（另有专门技能）
  6. ❌ 不做行业竞品数据对比（需另外调用行业分析技能）

8.3 数据准确性说明

  1. 所有数据均来自阿里国际站后台，实时抓取，无缓存
  2. 由于后台页面元素可能变动，个别数据可能出现"待人工核实"标记
  3. 报告中每项数据都注明了来源和抓取方法，可追溯核对
  4. 如发现数据错误，请告知Agent具体项，会立即重新抓取

8.4 使用建议

  1. 建议每周执行一次，形成周期性诊断记录
  2. 大促前/后各执行一次，评估活动效果
  3. 新员工接手店铺时执行一次，快速了解店铺现状
  4. 季度复盘/月度汇报可直接使用报告内容
