alibaba-product-health-check

阿里巴巴國際站商品健康度診斷技能。透過瀏覽器會話依次訪問商品管理、商品運營工作臺、資料參謀、行業徵品等後臺頁面，採集產品賽道結構、主營佔比、分組排序、產品分層、零效果產品、違規問題等6大維度資料，輸出結構化Word診斷報告並儲存到桌面。適用於所有阿里國際站店鋪（不限行業）。觸發關鍵詞：商品健康度、產品健康度、店鋪產品體檢、健康度診斷、店鋪產品盤點、產品結構分析。

阿里國際站商品健康度診斷 SKILL

概述

透過瀏覽器會話自動訪問阿里巴巴國際站賣家後臺，抓取商品健康度關鍵指標資料，基於行業標準和最優實踐生成診斷報告。適用於所有類目店鋪。

Step 1: 收集使用者輸入
  │  確認主營類目、店鋪行業、報告輸出偏好

Step 2: 檢查登入狀態
  │  訪問 i.alibaba.com，判斷是否需要登入

Step 2.5: 自動抓取店鋪真實名稱（必須執行）
  │  瀏覽器訪問後臺獲取公司英文名 + 阿里主頁連結
  │  用於報告封面，替代賬號郵箱

Step 1: 收集使用者輸入

執行前必須向使用者確認以下3個資訊（不確認則不能生成準確報告）：

資訊項 說明 示例
主營類目 使用者宣告的核心產品線（用於計算主營佔比） "安全帽 + 反光服 + 安全繩"、"USB充電器 + 資料線"、"寵物推車 + 寵物玩具"
店鋪行業 用於AI推算行業賽道比例建議 "PPE個人防護"、"3C電子配件"、"寵物用品"
報告檔名 輸出的Word檔名（預設：商品健康度診斷報告_日期.docx） 使用者可自定義

詢問模板：

在開始檢查前，請確認以下3個資訊：

1. 你的主營類目是什麼？（用於計算主營佔比，請寫清楚2-4個核心產品線）
2. 你的店鋪屬於哪個行業？（我會基於行業特性給出賽道比例建議）
3. 報告檔名希望自定義嗎？（預設：商品健康度診斷報告_YYYYMMDD.docx）

判斷規則： 如果使用者回覆中已經包含以上資訊（比如首輪請求就說"我是做安全帽的店鋪"），直接使用無需重複問；缺失才追問。

Step 2: 檢查登入狀態

訪問 https://i.alibaba.com/prod/product_manage#/product/online：

  • 頁面跳轉到 login.alibaba.com → 未登入，提示使用者完成登入後重試
  • 正常顯示商品管理頁 → 已登入，繼續

Step 2.5: 自動抓取店鋪真實名稱（必須執行）

目的： 報告封面使用真實公司名稱，而非賬號郵箱，適配多商家/多店鋪場景。

執行方式： 瀏覽器訪問阿里國際站賣家後臺，從以下任一位置讀取：

來源 操作
後臺頂部導航欄 通常顯示公司名稱或店鋪名
公司資訊頁 訪問 https://i.alibaba.com/company/company_info.htm
店鋪前臺連結 格式為 xxxx.en.alibaba.com，從後臺"我的店鋪"或位址列獲取

需記錄欄位：

欄位 說明 用途
company_name_en 公司英文註冊名稱 報告封面"店鋪名稱"
store_url 阿里主頁連結（xxxx.en.alibaba.com） 報告封面"主頁連結"
company_name_cn 公司中文名稱（如有） 可選，報告備註

如無法自動讀取（頁面超時/結構異常）：
- 降級方案：使用使用者提供的賬號郵箱作為店鋪標識，在報告中註明"（賬號郵箱）"
- 不允許憑猜測填寫公司名稱

報告封面寫法：

店鋪名稱：Hangzhou XXX Co., Ltd
主頁連結：xxxx.en.alibaba.com

Step 3: 資料採集（關鍵 · 分步執行）

重要原則：
1. 每次抓取只做一件事（瀏覽器session超時限制嚴格，一次任務超過5-8步大機率超時）
2. 每次抓取必須截圖確認（數字讀錯代價大）
3. 優先看頁面顯示的數字，其次才是JS console抓取
4. 不要用querySelectorAll('tr')數產品行（會把巢狀子行也數進去）

3.1 商品管理頁 - 賽道結構 + 違規問題

入口： https://i.alibaba.com/prod/product_manage#/product/online

依次執行5次篩選搜尋，每次記錄頁面右下角"總數"：

搜尋序號 篩選條件 記錄欄位
① 商品上下架狀態=已上架（公共產品） 已上架總數
② ①的基礎 + 商品型別=交易品 交易品數
③ ①的基礎 + 商品型別=商機品 商機品數
④ ①的基礎 + 商品質量分=0~3.9 低分品數
⑤ ①的基礎 + 是否有違規問題=是 已上架違規數

關鍵提示：
- 頁面元素引用（refs）會隨重新整理失效，遇到 Element not found 立即重新snapshot
- 總數位置：列表右下角，格式"總數: XXXX"
- 每次修改篩選條件後要等5秒讓資料載入

3.2 商品運營工作臺 - 產品分層

入口： https://hz-productposting.alibaba.com/product_operate/product_growth.htm

頁面直接顯示以下數字，用JS或直接讀頁面文字抓取：

// 抓取產品分層資料
const levels = {};
document.querySelectorAll('[class*="level-item"], [class*="tier"], .product-level').forEach(el => {
  const text = el.innerText;
  const match = text.match(/(低質品|普通品|潛力優品|優品|爆品)[（(](\d+)[)）]/);
  if (match) levels[match[1]] = parseInt(match[2]);
});
console.log(JSON.stringify(levels));

需記錄欄位： 低質品數 / 普通品數 / 潛力優品數 / 優品數 / 爆品數 / 右上角"重鋪診斷"數

3.3 資料參謀零效果產品 【專項最佳化 v2.0】

入口： https://data.alibaba.com/product/overview

⚠️ 鐵律：每頁固定10條產品，永不變動。任何顯示其他數字（如40條）都是取數方式錯了，不是頁面變了。

❌ 已知3大取數陷阱（嚴禁使用，血淚教訓）：

錯誤方法 會得到的錯誤結果 錯誤原因
保留預設勾選的"櫥窗產品" 數字異常少（如1款） 該過濾器只保留櫥窗產品，會遮蔽95%以上資料
document.querySelectorAll('tr').length 數字虛高4倍（如40/頁） tr包含表頭行、展開的子行、操作行等非產品行
讀 window.MYDATA_DATA.ineffTotal 數字不可控（如1605） 該欄位不對應零效果產品總數，是其他業務資料

✅ 標準取數流程（固化，不可變）：

🎯 檢查邏輯（統一口徑）：

指標 定義 達標標準
零效果產品佔比 ≥90天無效果產品數量 ÷ 已上架總數 × 100% < 5%

為什麼統一用90天：
- 90天是阿里國際站官方公認的產品沉睡分界線
- 不區分賽道可以簡化診斷邏輯，避免商機品/交易品資料無法精確拆分帶來的偏差
- 單一指標便於歷史對比和目標追蹤

標準取數步驟（一次抓取即可）：

Step 1: 訪問 https://data.alibaba.com/product/overview
Step 2: 等待8秒頁面載入
Step 3: 點選頂部"零效果產品"Tab，等待5秒
Step 4: 【關鍵】檢查"櫥窗產品"核取方塊，如已勾選必須取消
Step 5: "無效時長"下拉框選擇"大於等於90天"
Step 6: 點選"搜尋"按鈕，等待5秒
Step 7: 截圖頁面底部分頁器（必須截圖存證）
Step 8: 從分頁器讀取總頁數 XX（格式："1/XX" 或 "共 XX 頁"）
Step 9: 計算：零效果產品總數 = XX × 10

📐 計算規則（嚴格執行）：

基礎計算：總頁數與總數換算

場景 計算方式 示例
總頁數 ≥ 2 總頁數 × 10 = 總數 57頁 × 10 = 570款
總頁數 = 1 直接數當前頁產品行數（可能<10條） 顯示7條 = 7款
顯示"無資料" 總數 = 0 達標

末頁誤差說明： 末頁可能不足10條（如實際567款顯示57頁，末頁7條），產生±10條內的誤差屬於合理範圍，不影響診斷結論。

零效果佔比計算：

計算項 公式 達標標準
零效果產品佔比 ≥90天零效果總數 ÷ 已上架總數 × 100% < 5%

舉例說明：

假設：已上架2380款
     ≥90天零效果產品顯示57頁

計算過程：
├── 零效果產品總數 = 57頁 × 10條/頁 = 570款
├── 零效果產品佔比 = 570 ÷ 2380 = 23.9%
├── 警戒線：< 5%（對應 119款）
└── 狀態：嚴重超標（超出警戒線約5倍）

🔍 抓取質量校驗（每次必做）：

抓取完成後，立即執行以下2項校驗：

  1. ✓ 截圖校驗： 分頁器截圖必須能清晰看到"1/XX"數字，否則重新截圖
  2. ✓ 邏輯校驗： 零效果總數 ≤ 已上架總數（如零效果>已上架，一定錯了，需重抓）

任一校驗不透過 → 立即從Step 1重跑，不允許帶錯誤資料進入報告。

📝 報告中的資料表述規範：

【零效果產品檢查】
零效果產品（≥90天）：XXX款
├── 資料來源：XX頁 × 10條/頁 = XXX款
├── 已上架總數：XXXX款（來自商品管理頁）
├── 零效果佔比：XX.X%（零效果數 ÷ 已上架總數）
├── 警戒線：< 5%（對應 XX 款）
└── 狀態：[達標/超標X倍]

⚡ 效率最佳化建議：

  • 只需抓取一次（≥90天），耗時約1-2分鐘
  • 如遇下拉框互動失敗，直接用 browser_act 自然語言描述："在無效時長下拉框中選擇大於等於90天，點選搜尋按鈕"
  • 分母使用3.1章節抓取的已上架總數

3.4 主營產品佔比（按使用者宣告類目篩選）

入口： https://i.alibaba.com/prod/product_manage#/product/online

根據使用者在Step 1宣告的主營類目，逐個執行"商品所在類目"篩選：

  • 商品上下架狀態=已上架
  • 商品所在類目=[主營類目1] → 記錄數量
  • 清空 → 商品所在類目=[主營類目2] → 記錄數量
  • 清空 → 商品所在類目=[主營類目3] → 記錄數量

類目選擇器提示：
- 彈出的類目樹可能多級，逐級點選展開
- 若找不到精確類目，選擇最接近的父類目並在報告中註明實際選擇的類目名稱

計算： 各主營類目數量之和 ÷ 已上架總數 = 主營佔比

3.5 產品分組與排序

在商品管理頁左側或篩選區找到"商品分組"下拉框，讀取所有分組名稱的排序順序（從上到下）。

若分組較多，至少記錄前10-15個分組的：
- 分組名稱
- 每組產品數
- 是否屬於主營類目

3.6 行業定向徵品（可選，用於P2建議）

入口： https://hz-productposting.alibaba.com/product/collect_product.htm

讀取當前"交易品定招"和"商機品定招"下的：
- 全部商品數 / 待最佳化商品數 / 加速中商品數 / 加速完成商品數

用於報告中"P2 最佳化建議"的徵品補量方向。

Step 4: 行業賽道比例研究

基於使用者在Step 1宣告的店鋪行業和主營類目，輸出交易品/商機品最優比例建議。

判斷邏輯（內嵌行業知識）：

產品特徵 建議交易品佔比 定位
標準化極高、客單價低、決策週期短（如反光服、日用品、小家電配件） 60%~80% 引流款、RTS主力
標準化中等、客單價中、決策中等（如安全帽、寵物用品、家居） 40%~55% 平衡款
定製化強、客單價高、決策週期長（如安全繩、大件傢俱、工業裝置） 20%~30% 商機主導

若使用者提供的品類無法直接判斷，透過 web_search 或AI推理給出比例建議，並在報告中註明"基於行業邏輯推算"。

綜合店鋪建議比例區間： 根據主營各產品線加權平均後給出（如45%~55%）。

Step 5: 生成Word診斷報告

使用 docx skill 生成報告，儲存到桌面。

報告檔案路徑： /Users/[username]/Desktop/[使用者指定檔名].docx

報告章節結構（固定）

封面
├── 報告標題：商品健康度診斷報告
├── 店鋪名稱（公司英文名）/ 主頁連結 / 主營產品 / 檢查日期
│   ※ 店鋪名稱來自 Step 2.5 自動抓取，優先用公司英文名；抓取失敗則用賬號郵箱
└── 綜合健康評級（低風險/中風險/高風險，紅黃綠三色）

第一章：產品賽道結構
├── 交易品 vs 商機品比例表
├── 行業建議比例表（按產品線拆分）
├── 診斷結論
└── 整改建議

第二章：主營產品佔比 & 分組排序
├── 2.1 主營產品佔比（各類目數量+合計+佔比）
└── 2.2 產品分組排序檢查（表格展示前10分組+評估）

第三章：問題產品檢查
├── 3.1 低質品/低分品/違規品（三項歸零標準）
└── 3.2 產品分層分佈（爆品/優品/潛力優品/普通品/低質品）

第四章：零效果產品檢查
├── 檢查表（≥90天數量、佔比、警戒線）
├── 根本原因分析
└── 整改方案

第五章：違規侵權檢查
├── 已上架違規 / 已下架違規 / 商品雷達預警（三項歸零）
├── 平臺被動檢測侷限性說明
└── 持續監控路徑

第六章：優先行動清單
└── P0/P1/P2 三級優先順序 + 完成時限 + 操作路徑直達

報告樣式規範（去AI化 + 結構化）

樣式項 規範
字型 Arial（正文22pt，標題26-32pt）
主題色 深藍 #1A5276（品牌色）+ 深灰 #1A1A1A（正文）
狀態色 達標綠 #1E8449 / 預警橙 #D35400 / 嚴重紅 #C0392B
表格 淺藍表頭 #E8F0F7 + 灰色邊框 #CCCCCC
頁首/頁尾 頁首：報告標題+日期；頁尾：頁碼"第X頁/共Y頁"
結論表述 直接給數字+判斷+行動路徑，禁用"透過分析可以看出"等空話

報告資料完整性要求

  • 每個數字必須有來源（頁面/介面/使用者宣告）
  • 判斷必須有標準（"標準≥80%"、"警戒線<5%"）
  • 建議必須有路徑（"商品管理 → XXX → XXX"）
  • 時限必須有節點（"本週內"、"2周內"、"本月內"）

Step 6: 結果呈現

生成Word後，在對話中給出簡要摘要：

Word檔案已儲存至桌面：[檔案路徑]

【核心資料彙總】
- 已上架總數：XXXX款
- 交易品佔比：X.X%（行業建議XX%~XX%，[達標/不達標]）
- 主營佔比：X.X%（標準≥80%，[達標/不達標]）
- 零效果產品：XXX款（佔比X.X%，警戒線<5%，[達標/超標]）
- 違規產品：X款
- 重鋪診斷：XXX款

【首要問題】
1. [最嚴重的1-2個問題]

【首要行動】
1. [最優先的1-2個行動]

操作規範

  1. 資料準確性優先於速度：寧可多花時間核實數字，也不要把錯誤資料寫入報告
  2. 每次抓取必須截圖：截圖是數字準確性的最後保障
  3. 不要偽造資料：任何一項資料無法確認時，報告中明確寫"待人工核實"
  4. 保持中文輸出：報告全部中文，專業術語可保留英文原文
  5. 不要跨店鋪執行：一次執行只處理一個店鋪，不要在同一次任務中混合多店鋪資料

商品健康度診斷技能包

使 用 說 明 書

Alibaba Product Health Check · User Guide

技能名稱：alibaba-product-health-check

適用平臺：阿里巴巴國際站（Alibaba.com）

適用店鋪：全類目通用

一、技能概覽

1.1 這個技能能幫你做什麼

這是一個專為阿里國際站店鋪設計的商品健康度自動診斷工具。執行一次，即可獲得完整的店鋪產品健康度Word報告，覆蓋6大核心維度，直接指出問題、給出整改路徑。

簡單來說，你只需要一句話："幫我做商品健康度診斷"，剩下的全部自動完成。

1.2 覆蓋的檢查維度

序號檢查維度檢查內容
1產品賽道結構交易品/商機品數量佔比 vs 行業最優比例建議
2主營產品佔比主營類目產品數量佔全店比例（標準≥80%）
3產品分組排序核心分組是否靠前排列，非主營分組是否擠佔主營展示位
4問題產品清單低質品/低分品/違規產品數量（標準=0）+ 產品分層分佈
5零效果產品≥90天無曝光產品數量與佔比（警戒線<5%）
6違規問題已上架/已下架違規產品數 + 商品雷達異常預警

1.3 輸出結果

  1. 自動生成一份Word診斷報告，儲存到桌面
  2. 報告包含6章節 + 優先行動清單，共約15-20頁
  3. 所有資料帶原始來源+行業標準對比+可直接落地的整改路徑
  4. 對話中同步輸出核心資料摘要和首要問題

  2. 在 Accio Work 中開啟對應的 Agent（如"資深運營"）
  3. 技能會自動被 Agent 識別，無需重啟

依賴項說明

三、使用方法

3.1 一句話觸發

在對話中輸入以下任一關鍵詞，Agent會自動載入並執行本技能：

推薦觸發語適用場景
幫我做商品健康度診斷標準觸發語，最推薦
檢查一下店鋪產品健康度自然對話觸發
給我出一份產品體檢報告語義觸發
店鋪產品盤點一下簡短觸發
健康度診斷極簡觸發

3.2 完整執行流程（使用者視角）

Step 1：Agent 詢問你3個關鍵資訊

觸發技能後，Agent會先問你以下3件事（這些資訊決定報告的準確性）：

  1. 主營類目是什麼？（例如：安全帽 + 反光服 + 安全繩；或：USB充電器 + 資料線）
  2. 店鋪屬於哪個行業？（例如：PPE個人防護 / 3C電子配件 / 寵物用品）
  3. 報告檔名要自定義嗎？（預設：商品健康度診斷報告_YYYYMMDD.docx）

💡 提示：如果你在觸發語中已經說了"我是做安全帽的店鋪"，Agent會跳過重複詢問。

Step 2：Agent 自動開啟後臺採集資料

Agent會依次訪問4個後臺頁面，你會看到瀏覽器視窗自動開啟並翻頁：

  1. 商品管理頁 → 抓取賽道結構、違規資料
  2. 商品運營工作臺 → 抓取產品分層
  3. 資料參謀零效果 → 抓取沉睡產品資料
  4. 商品分組排序 → 檢查分組順序

⏱️ 全程約需 8-15 分鐘，取決於店鋪產品數量。

Step 3：Agent 生成Word報告

資料採集完成後，Agent會自動生成一份完整的診斷報告，儲存到桌面。

Step 4：Agent 輸出結論摘要

對話中同步給出核心資料+首要問題+首要行動，無需開啟Word也能快速瞭解店鋪狀態。

四、報告內容說明

每份報告固定6章結構，全部15-20頁，直接可用於團隊彙報或運營覆盤。

章節內容核心用途
封面綜合健康評級（低/中/高風險）一眼判斷店鋪整體狀態
第一章產品賽道結構（交易品vs商機品）判斷店鋪是否偏科，是否需要補發某類產品
第二章主營佔比 + 分組排序判斷主營產品是否佔主導，展示位是否合理
第三章低質品/低分品/產品分層找出需要下架、最佳化、升級的產品
第四章零效果產品清單找出沉睡產品，啟動批次重發計劃
第五章違規侵權檢查確認合規狀態，避免降權風險
第六章優先行動清單（P0/P1/P2）明確本週/2周/本月要做什麼，附操作路徑

五、執行前準備

為保證資料採集順利，執行前請完成以下準備：

✓ 必做項

  1. 開啟 Chrome 瀏覽器，登入阿里國際站賣家後臺（i.alibaba.com）
  2. 確認賬號有以下許可權：商品管理、資料參謀、商品運營工作臺
  3. 準備好回答3個問題：主營類目 / 行業 / 報告檔名

✓ 推薦項

  1. 執行前手動開啟資料參謀"零效果產品"Tab一次，確認頁面能正常載入
  2. 如果店鋪產品超過3000款，建議在執行前先關閉Chrome其他標籤頁，減少瀏覽器負載
  3. 每週固定時間執行（如週一上午），便於對比歷史資料

✗ 避免項

  1. 執行過程中不要手動操作瀏覽器（關閉標籤、跳轉頁面等）
  2. 不要在網路不穩定時執行（資料採集依賴多次請求）
  3. 不要同時執行兩次相同技能（會導致資料混亂）

六、常見問題與故障排除

Q1：Agent提示"需要登入"怎麼辦？

  • 直接在Chrome中開啟 https://i.alibaba.com/ 完成登入，然後回到對話中告訴Agent"我登入好了，繼續"即可。

Q2：零效果產品數量抓得不對（比如只顯示1條但實際有幾百條）

  • 原因：資料參謀零效果頁面預設勾選了"櫥窗產品"核取方塊，過濾了大部分資料。
  • 解決：技能已內建該場景檢測，會自動取消勾選。如果仍有問題，請手動開啟該頁面確認勾選項狀態並告知Agent。

Q3：主營類目篩選時找不到我的類目

  • 原因：阿里後臺類目名稱可能與你日常叫法不一樣（比如你說"反光服"，後臺叫"反光安全服"）。
  • 解決：Agent會嘗試匹配相近類目，並在報告中註明實際選擇的類目名稱。你也可以提前告訴Agent"我的類目在後臺叫XXX"。

Q4：報告中某項資料顯示"待人工核實"

  • 原因：某個資料點在自動化過程中未能可靠抓取（比如頁面互動失敗）。
  • 解決：按報告中給出的"手動核查路徑"人工補充資料。這是設計上的容錯機制，不是錯誤。

Q5：瀏覽器session超時中斷了怎麼辦？

  • 原因：單次瀏覽器任務超過約8分鐘會強制中斷。
  • 解決：Agent會自動拆分任務並續跑。你可以直接在對話中說"繼續"，Agent會從中斷處恢復。

Q6：報告數字與我手動核對的不一致

  • 原因：可能是頁面資料快取、時間點差異（如你8點看的是7點資料）或篩選條件不一致。
  • 解決：告訴Agent具體哪項資料不對，Agent會重新抓取核實。資料準確性優先，寧可多花時間也要保證正確。

七、行業標準參考

技能內建以下行業標準作為診斷基準，使用者也可以在觸發時自定義標準。

7.1 核心指標標準（通用）

指標達標標準說明
主營產品佔比≥ 80%主營類目產品數量佔全店已上架總數的比例

違規產品數量= 0平臺標記違規的產品，必須清零

交易品零效果佔比< 5%（≥60天）≥60天無曝光交易品佔已上架總數比例

7.2 賽道比例建議（按產品特性）

產品特徵建議交易品佔比典型品類示例
標準化極高、客單價低、決策週期短60%~80%反光服/耗材/小配件/日用品/工裝手套
標準化中等、客單價中、決策中等40%~55%安全帽/寵物用品/家居/小家電

八、能力邊界與免責說明

8.1 本技能能做什麼

  1. 自動抓取阿里國際站後臺6大維度的公開資料
  2. 基於內建行業標準生成結構化Word診斷報告
  3. 給出可直接落地的P0/P1/P2三級行動清單
  4. 每次執行都是獨立的（不依賴歷史資料快取）

8.2 本技能不做什麼

  1. ❌ 不主動修改後臺任何資料（只讀診斷，不執行操作）
  2. ❌ 不做主動侵權風險掃描（如圖片logo識別、商標詞庫比對）
  3. ❌ 不做外觀專利/發明專利查詢
  4. ❌ 不做影片內容侵權分析
  5. ❌ 不做P4P直通車資料關聯分析（另有專門技能）
  6. ❌ 不做行業競品資料對比（需另外呼叫行業分析技能）

8.3 資料準確性說明

  1. 所有資料均來自阿里國際站後臺，實時抓取，無快取
  2. 由於後臺頁面元素可能變動，個別資料可能出現"待人工核實"標記
  3. 報告中每項資料都註明了來源和抓取方法，可追溯核對
  4. 如發現資料錯誤，請告知Agent具體項，會立即重新抓取

8.4 使用建議

  1. 建議每週執行一次，形成週期性診斷記錄
  2. 大促前/後各執行一次，評估活動效果
  3. 新員工接手店鋪時執行一次，快速瞭解店鋪現狀
  4. 季度覆盤/月度彙報可直接使用報告內容
