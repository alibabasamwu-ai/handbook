alibaba-pmt-quanzhantui-diagnosis

阿里巴巴國際站「全站推（PMT / 全站推廣）」廣告投放資料診斷與最佳化操作手冊生成器。輸入一段時間的全站推資料（使用者上傳的匯出報告/Excel/PDF/截圖，或透過國際站後臺 MCP 拉取），自動產出一份結構化的「四層操作建議（計劃層 / 搜尋詞層 / 商品層 / 地域層）+ 7天后臺執行清單 + 30天目標值 + 風險提醒」Markdown 診斷報告。Use this skill whenever the user mentions 全站推、全站推廣、PMT、智慧推廣資料、方案包、商機成本、CPL、L1+點選佔比、商機轉化率、潛力優品計劃、把預算遷移/重組計劃、否定詞/降權詞清單、商品暫停/保留/遷移、國家預算降權、廣告診斷報告——even if they只是上傳了一份全站推匯出資料並說"幫我看看怎麼最佳化"或"基於這份資料生成最佳化建議"。This is the go-to skill for turning raw 全站推 performance data into an executable optimization playbook. 注意：本技能專做「全站推」診斷，不處理 P4P 關鍵詞競價細節（那走廣告分析技能），也不做選品/發品。

阿里國際站全站推資料診斷最佳化手冊生成器

把一份原始的「全站推」投放資料，轉換成一份和標杆報告同結構、可直接照著在後臺操作的最佳化手冊。

核心理念來自實戰標杆案例（見 references/benchmark-rongyi.md）：全站推效果不好，往往不是"完全沒效果"，而是預算被泛詞、混合產品池和低意向國家稀釋。 診斷的本質，是把預算從"大通投的混合計劃"遷移到"精準品類 + 精準規格詞 + 高意向國家"，並把弱品類拆成低預算測試線。

你的工作是：採集資料 → 按四層框架診斷 → 輸出可執行手冊。下面是完整流程。

Step 0：確定資料來源

按優先順序判斷資料從哪裡來：

  1. 使用者已上傳檔案（Excel / PDF / CSV / 截圖）→ 直接讀取解析，這是首選。
    - Excel/CSV：用 read 工具讀取。
    - PDF：用 read 工具讀取（支援文字抽取）。
    - 圖片截圖：直接看圖提取資料。
    - 如果是 .xlsx 且欄位複雜，可排程 office-suite SubAgent 以 [READ_MODE] 讀取後返回文字。
  2. 使用者沒有上傳檔案但已開通後臺 MCP → 透過國際站後臺拉全站推資料。
    - 用 accio-mcp-cli keyword 搜尋全站推 / 廣告相關工具（關鍵詞：全站推、PMT、廣告、營銷商機、方案包、商機），找到後呼叫拉取計劃/搜尋詞/商品/地域維度資料。
    - 若存在「國際站廣告分析」技能或 data-advisor 類介面，優先複用。
  3. 兩者都沒有 → 明確告訴使用者需要哪些資料，並給出匯出指引（見下方「需要的最小資料集」），不要憑空編造資料。

需要的最小資料集

為產出完整四層報告，理想情況下需要以下資料。缺哪層就在報告裡標註"該層資料缺失，無法診斷"，絕不編造：

  • 總盤：商機量、L1+商機量、點選量、L1+點選量、曝光量、詢盤量、TM諮詢量、訂單量（統計週期）。
  • 計劃層：每個計劃的名稱、商機/L1+商機、點選、詢盤、CVR(商機轉化率)、L1+點選佔比、消耗/CPL(商機成本，若有)。
  • 產品線/類目層（可選但強烈推薦）：每個產品線的產品數、商機、點選、詢盤、TM、商機轉化率、L1+點選佔比。
  • 搜尋詞層：搜尋詞、點選佔比、曝光佔比（用於算"佔比差"）。
  • 商品層：商品ID、所屬計劃、商機、點選、詢盤、CVR、L1+點選佔比。
  • 地域層：國家/地域、商機、詢盤、點選、TM、CVR、L1+點選佔比。

缺消耗/CPL時的處理：很多匯出檔案沒有消耗和CPL。此時計劃層用"商機/點選/詢盤/CVR/L1+點選佔比"做結構判斷即可，並在報告中註明"消耗/CPL口徑缺失，預算遷移判斷以結構指標為準"。這正是標杆報告裡的真實處理方式。

Step 1：算總盤體檢，先定調

讀完資料先算幾個關鍵比值，給整盤定一個"一句話結論"：

  • L1+商機佔比 = L1+商機 / 全站商機。≥70% 說明人群質量不差；偏低說明在引泛人群。
  • L1+點選佔比 = L1+點選 / 總點選。這是貫穿全報告的核心健康度指標，目標 ≥50%，優秀 ≥60%。
  • 正式詢盤佔商機比 = 詢盤量 / 商機量。偏低（如 <25%）說明 TM 輕諮詢過多、頁面與業務承接弱。
  • TM/詢盤結構：TM 遠多於正式詢盤 → 頁面篩選弱 + 業務話術需要前置篩選。
  • 訂單：線上訂單常為0，需提示使用者查線下成交，不要據此判定"完全無效"。

一句話結論的寫法（這是報告的靈魂，先寫它）：判斷"問題不是沒效果，而是預算被什麼稀釋了"，並指出預算應該遷移到哪裡。例：

本輪全站推不是"完全沒效果"，而是預算仍被泛詞、混合產品池和低意向國家稀釋。應立即把預算從"潛力優品/泛優品大通投"遷移到"核心品類 + 精準規格詞"，並把弱品類拆成低預算測試線。

Step 2：四層診斷（核心）

按「計劃層 → 搜尋詞層 → 商品層 → 地域層」依次診斷。每一層的判斷閾值、操作動作分類詳見 references/diagnostic-rules.md——開始診斷前先讀這個檔案，它是所有判斷標準的單一來源。

診斷時對每個物件（每個計劃/詞/商品/國家）輸出三段式：當前表現 → 判斷 → 具體操作。操作動作必須落到這幾類動詞之一：保留放大 / 拆分重組 / 降權 / 暫停 / 遷移 / 否定遮蔽 / 小預算測試。

2.1 計劃層

  • 對每個計劃算 CPL（如有）和 CVR、L1+點選佔比，判斷它是"最優計劃/有量但混雜/低效高CPC/小預算精修/立即暫停"中的哪一類。
  • 產出重組後的方案包結構：把混合計劃拆成「核心品類計劃（高預算40-45%）+ 穩定詢盤品類計劃（20-25%）+ 季節走量計劃（8-10%）+ 專案測試計劃（6-8%）+ 小眾高毛利測試（3-5%）+ 低預算補充流量（≤5%）+ 機動測試池（5%，每7天換詞）」。每個新計劃給：預算佔比、目標定位、產品池、目標詞。

2.2 搜尋詞層

產出三張清單：
- 必須放大的詞：點選佔比明顯 > 曝光佔比（佔比差為正）且意圖精準的詞。
- 立即降權/否定的詞：曝光佔比高但意圖過泛、或品類錯配的詞（"佔比差 > 0.5pct 且意圖泛"是降權紅線）。
- 品牌裸詞風險觀察：競品品牌詞（如 dyson/bissell 等）標註商標風險，不做主投。
- 若後臺無"否定詞"入口，給三步替代方案：移出觸發泛詞的產品 → 拆計劃降低泛品預算 → 用 P4P/關鍵詞推廣承接精準詞。

2.3 商品層

產出兩張清單：
- 立即保留並加權：高 CVR / 有詢盤 / 高 L1+點選的商品ID，給加權 + 詳情頁強化動作。
- 暫停或移出觀察：高點選0商機的商品ID（暫停紅線：7天點選≥20且0商機；或14天點選≥30且0正式詢盤/有效TM），給暫停/改標題/遷計劃動作。
- 商品操作要帶 商品ID，並寫清"遷到哪個新計劃"。

2.4 地域層

產出三張清單：
- 放大國家：有正式詢盤、CVR 健康的國家（正式詢盤優先順序 > 純TM）。
- 保留低預算觀察：資料好但全是TM的國家（要警告"不可盲目放量，先讓業務覆盤客戶型別"）。
- 降權/遮蔽觀察：高點選0商機國家（降權紅線：點選≥30且0商機）。
- 關鍵原則：國家預算不按"商機數"單獨決策——純TM多的國家不等於高質量，需業務覆盤後再放量。

Step 3：7天后臺執行清單

把診斷結論排成可以照做的 7 天節奏（這是報告最實用的部分，必須有）：

  • Day 1 計劃止血：暫停最低效計劃、大幅降第二低效計劃預算、清理核心計劃裡的0商機產品後再加預算、啟動混合計劃拆分。
  • Day 2 搜尋詞處理：執行放大清單、降權/否定清單、品牌風險觀察。
  • Day 3 商品池重組：建立新方案包計劃（RY-01/02/03…命名）、把低效品統一進低預算池。
  • Day 4 地域設定：核心計劃鎖定高意向國家、測試計劃給東南亞/中東低預算、高點選0商機國家降權。
  • Day 5 詳情頁快速修復：核心品類首屏加 OEM/規格/材質/認證關鍵詞；每個核心頁加詢盤欄位（ID/OD、長度、介面、材料、採購數量、目標市場、是否OEM包裝）。
  • Day 6 業務承接同步：TM首句改成篩選型話術（問規格/月採購量、引導MOQ）；高意向國家詢盤要求1小時內首響。
  • Day 7 覆盤閾值：定下計劃保留/商品暫停/詞降權/國家降權的量化標準（見 diagnostic-rules.md）。

Step 4：30天目標值 + 風險提醒

  • 30天目標值表：針對全站商機成本、核心計劃商機成本、L1+點選佔比、正式詢盤佔商機比、低效計劃消耗佔比、泛詞曝光佔比、平均回覆時長，各給"當前 → 30天目標"。目標要可量化、基於當前值合理收緊（如商機成本降到當前的 70-80%、L1+點選佔比 +7pct 左右）。
  • 風險提醒（固定要點 + 按資料補充）：不要一刀切關停全站推（會損失模型學習）；不要只追 CPC 降低（低CPC泛流量帶來無效TM）；不要讓弱品類與核心品類共用預算池；不要用品牌裸詞做主預算；所有改動按3天小週期觀察（一次性改太多會重置系統學習）。
  • 最終操作優先順序：用"先停 → 再拆 → 再放 → 再篩 → 再承接"五步收尾，給出最高優先順序的商品ID放大清單。

最終輸出一份 Markdown 報告，檔名建議 {店鋪名}_全站推診斷_{統計週期}.md，寫入工作目錄。結構如下（與標杆報告對齊）：

關鍵紀律（避免報告失真）

  1. 零資料幻覺：所有商品ID、數字、國家、搜尋詞必須來自輸入資料。某層資料缺失就如實寫"該層資料缺失，建議補充匯出後再診斷"，絕不編造ID或數字湊數。
  2. 結論先行：每個表格/清單前先給判斷結論，再列證據。
  3. 操作必須可執行：每條建議落到具體動詞 + 具體物件（計劃名/商品ID/搜尋詞/國家）+ 具體數值（預算佔比/降幅/天數）。"最佳化一下""注意一下"這種話不允許出現。
  4. 預算遷移是主線：始終圍繞"從哪裡抽預算、遷到哪裡"組織建議，而不是孤立地看單個指標。
  5. 正式詢盤 > TM：判斷國家/商品價值時，正式詢盤權重遠高於TM輕諮詢。
  6. 3天小週期觀察：所有改動提醒按小週期驗證，避免系統學習重置。

匹配使用者語言輸出（預設中文）；國際站術語保持英文：L1+、CVR、CPL、TM、MOQ、OEM、SKU、HVAC、FOB。

六、7天覆盤量化閾值（Day 7 用）

  • 計劃保留標準：7天內 CVR ≥ 3.5% 且 L1+點選佔比 ≥ 50% 且 有詢盤或有效TM。
  • 商品暫停標準：7天點選 ≥20 且 0商機；或 14天點選 ≥30 且 0正式詢盤/有效TM。
  • 詞降權標準：曝光佔比 − 點選佔比 > 0.5pct 且意圖泛。
  • 國家降權標準：點選 ≥30 且 0商機；或商機全為低價/無規格/零售。

七、30天目標值設定邏輯

基於當前值合理收緊，不要拍腦袋：
