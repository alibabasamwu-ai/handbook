你好，我給了你一個 alibaba-business-review.zip，這是「阿里巴巴國際站 30/90 天店鋪業務覆盤」技能包。請嚴格按下面步驟執行，全程 bash，不要跳步、不要自己發揮，最終交付一份 HTML 看板 + 4 個檔案。

第 0 步 · 心智校準（先讀，決定質量）

本技能有 3 條鐵律，違反任何一條都會讓覆盤作廢，請你先記住：
1. 會話按子賬號隔離：阿里 IM 會話只能按單個業務員賬號拉。必須先查全部子賬號再遍歷採集，只拉主賬號會漏掉 90%+ 的客戶。（指令碼 collect_live.py 已封裝好，照用即可。）
2. 主營品類只認真實資料：店鋪主營由指令碼從業務員訊息自動推斷，嚴禁你從 skill 自帶的案例/樣例檔案（cases/examples）猜測主營——那些是演示資料，跟當前店鋪無關。
3. 零編造：所有數字、客戶名、背調結論必須來自真實採集資料或帶 source_url 的公網檢索，查不到就如實標註，不許填充示例資料。

第 1 步 · 安裝

unzip alibaba-business-review.zip -d /tmp/abr
cp -r /tmp/abr/alibaba-business-review ${agent_skills}/
ls ${agent_skills}/alibaba-business-review/SKILL.md   # 確認安裝成功

第 2 步 · 預熱（讀取方法論 + 反幻覺鐵律，避免冷啟動）

cd ${agent_skills}/alibaba-business-review
rm -rf scripts/__pycache__ .cache 2>/dev/null
python3 scripts/preheat.py

把預熱輸出完整讀一遍，尤其開頭的「🛑 主營品類鐵律」和方法論（BANT/SPIN/客戶分層規則）。這一步讓你具備和標杆一致的判斷標準。

第 3 步 · 採集真實資料（核心，照抄命令）

cd ${agent_skills}/alibaba-business-review
python3 scripts/collect_live.py 90
  • 這個指令碼會自動：查詢店鋪全部業務員子賬號 → 遍歷每個賬號拉近90天會話 → 拉全訊息 → 寫入 data/chats.json。
  • 跑完會列印「✅ 寫入 … X 有效會話 / Y 訊息」。正常品牌店應有幾百會話、幾千條訊息；如果只有個位數會話，說明子賬號沒拉到，檢查阿里賬號授權後重跑。
  • 店名可選：python3 scripts/collect_live.py 90 --shop "你的店鋪名"（不填則看板顯示通用名）。
  • 不要手填主營品類，step1 會自動從業務員訊息推斷。

第 4 步 · 跑評分 + 業務員聚焦診斷（照抄）

cd ${agent_skills}/alibaba-business-review
rm -rf scripts/__pycache__ 2>/dev/null
python3 scripts/step1_customer_scoring.py     # 客戶分層（會列印自動推斷的主營）
python3 scripts/step2_health_diagnosis.py     # 跟進健康度訊號（含買家原話）
python3 scripts/step3_team_diagnosis.py        # 團隊三維診斷
python3 scripts/step6_seller_focus.py          # ⭐業務員聚焦診斷（一人一檔：核心問題+共性/個性+提升+客戶行動）

第 5 步 · Top 客戶公網背調（深度，接入聚焦模組）

對 step1 輸出裡 Tier=A/B 的重點客戶做公網背調（建議 Top 12~50，越多越好）：
- 讀 reports/step1_customer_scoring.json 取 A/B 檔客戶的 buyer_name + buyer_country。
- 分批（每批 4-5 人）並行派 browser SubAgent 做 OSINT（web_search 組合搜"姓名+國家+行業"），按 workflow/05-customer-intel.md 規範。
- 硬約束：每條結論必須帶 source_url；查不到標 found:false，不編造；同名歧義要標註。
- 兩個產出：
1. 彙總成 reports/top50_deep_intel.md（或 core10_customer_intel.md）——分梯隊的深度背調報告。
2. ⭐ 把結構化結論整理成 reports/customer_intel.json（格式見 reports/customer_intel.example.json：buyer_name → {company,type,match,role,strategy,source}），這樣背調情報會自動接進業務員聚焦模組的每個重點客戶卡片。

第 6 步 · 重跑 step6 + 生成看板 + 審計

cd ${agent_skills}/alibaba-business-review
rm -rf scripts/__pycache__ 2>/dev/null
python3 scripts/step6_seller_focus.py          # 重跑：接入 customer_intel.json 背調情報
python3 scripts/step4_audit_and_dashboard.py   # 生成 HTML 看板（含業務員聚焦+背調閉環）
python3 scripts/step5_verification_csv.py      # 買家核驗表 CSV
python3 audit/checklist.py --html reports/alibaba_review_dashboard.html \
  --reports-dir reports/ --chats data/chats.json --out logs/audit.json
  • 目標 P0 28/28、Verdict PASS。P1 不強制（E1 把買家原話裡 "is undefined" 誤報是真實原文，忽略）。
  • 若 P0 沒滿分：A9/A10 = 核驗表/背調沒生成；B 類 = 採集缺欄位。回頭補，不要改 skill 程式碼。
