# 标杆图定稿循环协议 · v3.0 新增

> 这是 v3.0 工业化流程「**阶段 B：标杆定稿**」的执行协议。
> 核心理念：**先用 1 张标杆图反复打磨到商家"定稿"，再以此标杆复制全套**。这样可以：
> - 把"6 图都不满意 → 全部重来"的最坏情况，降级为"标杆 1 张反复改"的局部损耗
> - 让批量复制时所有图共享同一套视觉/文案/布局基因，全套一致性最大化
> - 用户的反馈聚焦在 1 张图，决策成本最低、定稿质量最高
>
> **定稿循环上限**：⚠️ 不设上限（按商家明确指令"定稿"为终止信号）。每轮必写审计日志，避免无限循环时丢失上下文。

---

## 标杆图选择规则

| 出图任务 | 标杆图候选（按推荐顺序） |
|---------|--------------------|
| **详情页 6 图** | 第 3 图 USP 核心卖点（信息密度最高，最能暴露问题） |
| 备选 | 第 1 图主形象（如商家先关心首图） |
| **营销图 12 张** | 第 3 图 USP 海报（与详情页标杆共享视觉风格） |
| **节日促销批量海报** | 主推节日的中文/英文双语版 1 张 |
| **SKU 矩阵图** | TOP1 主推 SKU |

主代理**主动提议**标杆图，并说明选择理由；商家可改选其他图位作为标杆。

---

## 定稿循环 6 步（每轮）

```
┌────────────────────────────────────────────────────────────┐
│ 轮次 N 启动                                                 │
│   ↓                                                        │
│ B1  主代理出标杆图 v(N) → 落地 + 同步给商家                 │
│   ↓                                                        │
│ B2  主代理执行 R5 10 项抽检 + 给出总分                      │
│   ↓                                                        │
│ B3  主代理列出 v(N) 的「3 项最大改进空间」+ 推荐下轮方向    │
│   ↓                                                        │
│ B4  商家反馈：① 定稿 / ② 微调（指定改 X）/ ③ 大改（推翻重做）│
│   ↓                                                        │
│ B5  主代理写入审计日志 ITERATION_LOG.md（追加 1 行）        │
│   ↓                                                        │
│ B6  如商家未"定稿" → 调整 prompt 进入轮次 N+1               │
│     如商家"定稿"  → 锁定 BENCHMARK_LOCK.md → 进入阶段 C    │
└────────────────────────────────────────────────────────────┘
```

### B1 出图

- 必须遵守 R3.2 反 AI 三件套（G1+G2+G3+图位 BRIEF）
- 必须用 image_edit + 本地绝对路径 reference_images（如有真实素材）
- 文件命名：`<产品简称>_BENCHMARK_v{N}_<YYYYMMDD-HHMM>.jpg`
- 落地路径：`<根目录>/01_标杆定稿/<标杆图位名>/`（与最终批量出图分文件夹）

### B2 抽检（套用 R5 10 项验收清单）

主代理 see_image 自检，输出标准抽检表格（不可只说"已生成请查看"）。

### B3 三项改进空间提示

每轮无论评分多少，都必须主动列出"还可以改进的 3 项"，避免商家以为已经满分。模板：

```
## 💡 标杆图 v{N} 的 3 项可改进方向

1. **<改进点 1>**：建议方向（如"加强光影对比，让产品边缘更立体"）
2. **<改进点 2>**：建议方向
3. **<改进点 3>**：建议方向

下轮 v{N+1} 默认采纳第 1 项；如需采纳其他/全部，请告知。
```

### B4 商家反馈（3 选 1）

主代理用 ask_user 提供 3 选项卡片：

```
您的决定：
a) 🎯 定稿 v{N}（锁定为标杆，进入批量复制阶段 C）
b) ✏️ 微调（告诉我改什么：颜色 / 文案 / 构图 / 光感 / 数量）
c) 🔄 大改（推翻当前方向，我重出 v{N+1}）

⚠️ 提示：若 v{N} 总分 ≥ 9.5 且您选 b/c，下一轮我会保留 v{N} 作为参考底图，
保证不退化（避免越改越差）。
```

### B5 审计日志（ITERATION_LOG.md）

**强制写入**，每轮 1 行，定稿后形成完整迭代史。位于 `<根目录>/01_标杆定稿/ITERATION_LOG.md`。

```markdown
# 标杆图迭代日志 · <产品简称> · <标杆图位名>

| 轮 | 时间 | prompt 版本 | 抽检总分 | 商家选择 | 本轮改了什么 | 下轮要改什么 |
|----|------|-----------|---------|--------|------------|------------|
| v1 | 2026-05-26 14:32 | P1.0 | 8.5/10 | b 微调 | - | 加强光影 + 文案换为 "Built for Harsh Climate" |
| v2 | 2026-05-26 14:45 | P1.1 | 9.2/10 | b 微调 | 光影 ✅ 文案 ✅ | SKU 颜色变体偏淡，加饱和度 |
| v3 | 2026-05-26 14:58 | P1.2 | 9.6/10 | a 定稿 | 颜色 ✅ | - |
```

### B6 收敛或继续

- 商家选 **a 定稿** → 触发"标杆锁定"产出 BENCHMARK_LOCK.md → 进入阶段 C
- 商家选 **b 微调** → 主代理只改商家指定项，其他保留 → 进入 v(N+1)
- 商家选 **c 大改** → 主代理回到 Step 3.5 创意提案表重新策划，但保留 CONFIRMED_FACTS（事实层不重做）

## 定稿信号识别（防止误锁）

主代理识别"定稿"为以下任一明确信号，**不可推测**：

| ✅ 触发定稿 | ❌ 不可推测定稿 |
|------------|--------------|
| "定稿" / "锁定" / "就这版" / "ok 用这个" | "不错" / "还行" / "可以" / "差不多" |
| "Lock it" / "Final" / "Approved" | "Looks good" / "Not bad" |
| "我选 a" / "选 a" | 商家 5 分钟未回复（按 R6.1 默认值 ≠ 定稿） |
| "进入下一步" / "开始批量" | "下一张吧"（这是跳过该图，不是定稿）|

**模糊时主代理必须追问**：

```
您说"可以"，是指：
a) 🎯 这版定稿，开始批量复制其他 5 张？
b) ✏️ 还要再改一版？
```

## BENCHMARK_LOCK.md 标准模板（阶段 C 的输入）

定稿后立即产出，位于 `<根目录>/01_标杆定稿/BENCHMARK_LOCK.md`。

⚠️ 这是阶段 C 批量复制的**唯一锁定源**，所有 5 张同图位/同系列图必须严格继承此锁。

```markdown
# 标杆锁定 · <产品简称> · <标杆图位名> · v{N}

## 0. 锁定元信息
- **定稿时间**：YYYY-MM-DD HH:MM
- **总迭代轮数**：N
- **最终评分**：X.X / 10
- **商家签字**：商家原话引用："____"

## 1. 视觉锁（VISUAL LOCK）—— 视觉DNA
- **主色**：#XXXXXX（HEX）+ 名称（如"深空蓝 Deep Navy"）
- **辅色**：#XXXXXX + #XXXXXX
- **强调色**：#XXXXXX（用于数据徽章/CTA）
- **光感风格**：硬光 / 柔光 / 棚拍光 / 自然光
- **场景调性**：户外/室内 + 季节 + 时段（如"中东沙漠正午"）
- **机位角度**：正面 15°俯视 / 侧 45° / 顶视
- **景深**：浅景深虚化 / 全景深锐利
- **图像质感关键词**（用于继承到批量 prompt）：____

## 2. 文案框架锁（COPY FRAMEWORK LOCK）
- **主标语风格**：动词开头 / 数据型 / 痛点反问？
- **字数上限**：主标 ≤ 6 词 / 副标 ≤ 12 词
- **字体家族**：Sans-serif Bold（如 Montserrat Black）+ 字号比例
- **数据徽章格式**：圆角矩形 + 黑底白字 / 黄底黑字 / X% OFF / X-Year Warranty
- **CTA 行动按钮**（如有）：____
- **多语言版本规则**：英文 + 主推市场语种 + 字符间距规则（阿拉伯语 RTL）

## 3. 布局栅格锁（GRID LOCK）
- **画布比例**：1:1（详情页主图强制）/ 16:9（横幅）/ 9:16（移动）
- **安全边距**：上下各 X%；左右各 X%（含平台水印安全区）
- **主体占比**：60-70%（官方推荐）
- **文字区域**：占画布上 / 下 / 左 / 右 X% 位置
- **logo 位置**：左上角 / 右下角；尺寸占比 ≤ 8%
- **认证图标位**（如有）：底部居中横排，间距均匀

## 4. 严禁项黑名单（继承自 CONFIRMED_FACTS §3）
- ❌ ____ （如"严禁 FDA / CFDA / MFDS 等未确认认证"）
- ❌ ____ （如"严禁竞品 logo / 未授权人物头像"）
- ❌ ____ （如"严禁出现 best/cheapest/No.1 平台违规词"）

## 5. 批量复制时的"允许变量"清单（其他都要锁）
- ✅ 允许变化：产品角度/SKU 颜色/具体卖点文案内容/场景细节物（如沙漠→雪山）
- 🔒 严禁变化：主色/字体/布局栅格/光感风格/严禁项黑名单

## 6. prompt 模板（4 段全文，含 G1+G2+G3+图位 BRIEF）
> 直接复制到阶段 C 批量复制时使用，仅替换图位 BRIEF 段

[G1 REALISM CONTRACT]
____

[G2 PRODUCT FACTS LOCK]
____（继承 CONFIRMED_FACTS）

[G3 CATEGORY VISUAL BRIEF]
____（继承 v{N} 定稿后的视觉关键词）

[图位 BRIEF — 标杆图位]
____（v{N} 终版 prompt）
```

## 阶段 C：批量复制规则

- ⚠️ 严禁绕过 BENCHMARK_LOCK.md 直接生成
- 所有后续图的 prompt 必须以 BENCHMARK_LOCK §6 为模板，**只替换图位 BRIEF 段**
- 抽检时除 R5 10 项外，额外加 3 项**一致性验收**：
  - 主色色差 ≤ 5%
  - 字体识别率 = 100%
  - 布局栅格偏移 ≤ 画布宽度的 3%
- 任何一项一致性不达标 → 立即回炉，禁止"差不多就行"

---

## 与硬规则的联动

| 联动点 | 行为 |
|--------|------|
| **R1 强制门禁** | 增加 R1.5：BENCHMARK_LOCK.md 未落地 → 严禁进入阶段 C 批量出图 |
| **R3.2 反 AI 风** | 阶段 C 的 G1/G2/G3 必须继承自 BENCHMARK_LOCK §6，不得重新写 |
| **R5 抽检** | 阶段 C 增加 13 项验收（10 项 R5 + 3 项一致性）|
| **merchant-self-evolving** | 定稿轮数 / 商家偏好风格 / 高频改动项 → 写入 `user_preferences.iteration_pattern` |

## ⭐ B7 中途换档分支（v3.1 新增）

**触发条件**：定稿循环任意轮，商家说"换种风格试试" / "这风格不对" / "换 C 档" / "感觉太工业了，能不能更生活化"。

**处置流程**（主代理 SOP）：

```
1. 主代理识别换档意图（不可静默执行）
   ↓
2. 用 ask_user 弹出二次确认：

   ⚠️ 检测到您想换风格档。
   当前档：{从 VISUAL_STYLE_LOCK.md §1 读出}
   建议新档：{基于商家描述匹配，如"更生活化"→C}
   兼容度：{🟢/🟡/🔴 查 visual-style-presets.md §4 矩阵}
   后果：当前标杆 v1-v{N} 全部归档，从 v1 重新开始定稿循环。

   请选：
   a) 确认换到 {新档}，清空标杆历史从 v1 重启
   b) 不换，继续打磨当前 v{N}
   c) 看 5 档示意图后再决定
   d) 我想换的是另一档（请说明）
   ↓
3a. 商家选 a) → 执行换档：
    - 归档 ITERATION_LOG.md → ITERATION_LOG_style{旧档}_archived.md
    - 归档 BENCHMARK 历史图 → 01_标杆定稿/_archived_style{旧档}/
    - 更新 VISUAL_STYLE_LOCK.md §1.修改记录加一行（时间/旧档/新档/原因）
    - 新建空白 ITERATION_LOG.md
    - 回到 B1 重出新档 v1
   ↓
3c. 商家选 c) → 用 image_generate 出 5 张同款 5 档示意图 → 让商家点选
   ↓
3d. 商家选 d) → 让商家说明 → 走 a) 流程换到指定档
```

**严格约束**：
- 不允许"档位渐变"（如 A→B 微调）。换档就是切换档，不允许混合
- 不允许"先按 A 档出剩余 5 张再说"——VISUAL_STYLE_LOCK 没改，阶段 C 必拒
- 主代理在弹出二次确认前**禁止**先调 image_generate 出新档图（避免误导）

## 反模式（v3.0/v3.1 重点封堵）

- ❌ 商家说"差不多"就推进 → 必须追问明确信号
- ❌ 不写 ITERATION_LOG → 第 N+1 轮记不清前 N 轮改了什么，循环退化
- ❌ 不产出 BENCHMARK_LOCK 直接批量 → 5 张图视觉风格漂移
- ❌ **v3.1** 商家说"换风格"直接执行 → 必须 B7 二次确认且明告归档代价
- ❌ **v3.1** 不更新 VISUAL_STYLE_LOCK.md §1.修改记录 → 阶段 C 视觉抽检失去溯源
- ❌ 阶段 C 抽检"差不多就行" → 一致性不达标 = 全套报废
- ❌ "假定稿"（主代理预判商家满意直接进 C）→ 必须有商家明确"定稿"信号
