# 标准商家互动卡片库 · v2.0

> 本文件是 SKILL v2.0 的「商家互动话术规范」。每个决策点都有一张标准 ask_user 卡片：包含**触发时机 / 标准问法 / 选项设计 / 默认推荐 / 商家典型回答与应对脚本**。
>
> ⚠️ 任何执行 AI 在对应 Step 都**必须**调用对应卡片的 `ask_user`，不可省略、不可改写问题主体。商家答完后按"应对脚本"路由下一步。

---

## Card 1 · 存放路径与产品简称

**触发时机**：Step 0 商家说明本次目标后**立即**调用，无任何前置条件。

**核心目的**：图片是商家资产，存放位置与命名必须商家亲自确认，不能 AI 默认决定。这是 R1.1 强制门禁。

### 标准 ask_user 调用

```
ask_user(mode="form", questions=[
  {
    question: "📁 您希望素材存放在哪里？",
    header: "存放路径",
    options: [
      { label: "默认（项目内）", description: "<当前工作目录>/<商家>_<YYYYMMDD>_<时分>/" },
      { label: "桌面文件夹", description: "~/Desktop/国际站素材/<商家>/<产品>/（团队多人协作友好）" },
      { label: "我自己输完整路径", description: "下一步告诉我具体位置（网盘/共享盘等）" }
    ],
    recommended: 0,
    allowSkip: false
  },
  {
    question: "🏷️ 本次主推产品的「文件命名简称」？",
    header: "产品简称",
    options: [
      { label: "<根据商家描述自动抽取>", description: "如 SolarStreetLight-100W、FoldingChair-Camping" },
      { label: "用商品 ID", description: "精准但人眼不易识别，如 1600911862199" },
      { label: "我自己输", description: "下一步告诉我（团队认得出的简称最好）" }
    ],
    recommended: 0,
    allowSkip: false
  }
])
```

### 商家典型回答与应对脚本

| 商家回答 | 你必须做 |
|---------|--------|
| 全选默认 | **完整复述**确认："好，我把素材存放在 `<完整路径>`，命名简称用 `<简称>`，对吗？"（防事后扯皮） |
| 选"我自己输路径" | 用 mode="chat" 追问："请告诉我完整路径，例如 `/Users/xxx/Desktop/...`" |
| 给的路径不存在 | 用 `bash mkdir -p "<路径>"` 创建 → 回显绝对路径："已为您创建目录 `<绝对路径>`" |
| 选"用商品 ID" | 静默写入会话内存，不再询问 |
| "随便""你看着办" | **拒绝省略**，按推荐项给商家一个 yes/no："那我用 `<默认路径>` + `<默认简称>`，OK 吗？"（必须商家明确说 OK） |

**完成本卡后写入会话内存**：`{ root_path, product_alias }`。后续所有 Step 4 文件命名必须使用这两个字段。

## Card 1.5 · 历史素材复用门禁（v2.0.2 新增 · 反重复浪费）

**触发时机**：Card 1 完成后、调 Card 2 之前。主代理必须先在 `<根目录上一级>` 用 glob 扫描历史包：`<商家昵称>_*` 或 `<产品简称>*`。

**触发条件**：找到 ≥ 1 个历史素材包 → 必须出本卡（找不到则跳过，直接 Card 2）。

**核心目的**：商家本意可能是"看看上次做了啥/补几张缺的"，不是"再花一倍 i 豆从头做"。

### 标准 ask_user 调用

```
ask_user(mode="form", questions=[{
  question: "🗂 我发现您历史已有 N 个 <产品简称> 素材包，本次想怎么做？",
  header: "复用判定",
  options: [
    {
      label: "A. 全新一套",
      description: "忽略历史，照常 Step 1-5 全部重出（适合产品规格/卖点有大改）"
    },
    {
      label: "B. 复用 + 仅补差",
      description: "我列出历史已有的图位，仅生成缺失的 N 张（最省 i 豆，推荐）"
    },
    {
      label: "C. 直接给清单",
      description: "不做新图，把历史素材整理成交付清单给我（跳过 Step 1-4 直接 Step 5）"
    }
  ],
  recommended: 1,
  allowSkip: false
}])
```

### 商家典型回答与应对脚本

| 商家选择 | 你必须做 |
|---------|--------|
| A 全新 | 正常进入 Card 2（A/B 路径） |
| B 复用补差 | 列出历史包内的图位清单 → 让商家勾选缺失项 → 仅对勾选项跑 Step 4，其它直接复用历史路径 |
| C 直接清单 | 跳过 Step 1-4，直接调 Step 5 整理交付清单（含历史本地路径 + CDN URL） |
| "你帮我看看" | 默认 B（最省钱），把历史 vs 标准全套的 diff 表展示后让商家二次确认 |

**完成本卡后**：B/C 路径下 Card 2 跳过；A 路径正常进 Card 2。

## Card 2 · 原素材来源（A/B 二选一）

**触发时机**：Card 1 完成后**立即**调用。

**核心目的**：原素材决定了后续所有创意的真实性。商家必须明确告诉 AI 走 A 还是 B 路径。

### 标准 ask_user 调用

```
ask_user(mode="form", questions=[{
  question: "📦 请选择本次的原素材来源：",
  header: "素材来源",
  options: [
    {
      label: "A. 后台一键拉取",
      description: "我从您的国际站后台抓产品 → 列系列清单与图让您挑（适合批量出图、后台素材完整）"
    },
    {
      label: "B. 您直接上传图片",
      description: "您上传产品图 + 提供产品名称（适合新品 demo、后台图质量差、做单品 Demo）"
    },
    {
      label: "C. 复用历史素材包",
      description: "（仅当 Card 1.5 未触发时显示）我之前做过相似产品 → 列我历史包让我挑"
    }
  ],
  recommended: 0,
  allowSkip: false
}])
```

### 商家典型回答与应对脚本

| 商家选择 | 你必须做 |
|---------|--------|
| A 后台拉取 | 启动 `sessions_spawn(agent_id="browser", task="...")` 走 references/source-acquisition.md A 方案。**抓图后必须 see_image 抽样校验**（防抓错图） |
| B 商家上传 | mode="chat"，attachmentSlot 接受 image，要求商家上传 1-6 张产品图 + 产品名称 |
| "我都试试" | 默认走 A，告知商家："我先从后台抓，如果质量不达标会自动回退到您上传" |
| "我后台没东西" | 自动转 B 方案 |
| 后台抓图失败 3 次 | 触发 R6 降级 → 主动建议商家："后台抓取异常，建议您直接上传 1-2 张代表性产品图" |

**完成本卡后必须有的产物**：`{产品清单}` + `{每个产品至少 1 张可用原图，存于 00_原素材/}`，否则不可进 Step 2。

## Card 3 · 生成范围（详情页/营销图多选）

**触发时机**：Step 2 行业洞察简报展示给商家之后。

**核心目的**：让商家明确"本次要做哪些图"，避免 AI 自作主张全套出图烧 i 豆。

### 标准 ask_user 调用

```
ask_user(mode="form", questions=[
  {
    question: "📐 详情页 6 图 — 要做几个产品的全套？",
    header: "详情页",
    options: [
      { label: "1 个产品（试点）", description: "推荐首次合作时用，6 张图试水" },
      { label: "5 个产品", description: "30 张图，主推系列覆盖" },
      { label: "10 个产品", description: "60 张图，全系列铺底" },
      { label: "本次不做详情页", description: "只做营销图" }
    ],
    recommended: 0
  },
  {
    question: "🎨 营销图 12 张清单 — 您要做哪些？（多选）",
    header: "营销图",
    multiSelect: true,
    options: [
      { label: "01 Catalog 封面 + 03 USP 海报 + 04 竞品对比", description: "WhatsApp/邮件谈客户三件套（最常选）" },
      { label: "全部 12 张", description: "完整素材包：含 AboutUs / 认证墙 / 工厂 / 案例 / 包装 / MOQ / 节日 / 报价单 / 签名" },
      { label: "我手动勾选", description: "下一步逐项勾选" },
      { label: "本次不做营销图", description: "只做详情页" }
    ],
    recommended: 0
  }
])
```

### 商家典型回答与应对脚本

| 商家选择 | 你必须做 |
|---------|--------|
| 详情页 1 个 + 营销三件套 | 共 **9 张图** → 进 Step 3.5 出 9 张创意提案 |
| 全选 12 张营销图 + 不做详情页 | 共 12 张 → 提醒："营销图 12 张含「业务员签名图」需您提供姓名/邮箱/WhatsApp，可以吗？"（特殊确认） |
| 详情页 10 个 + 全部 12 张营销 | 共 72 张 → **必须提示工时与 i 豆消耗**："这是大批量，预计 30+ 分钟，i 豆约消耗 X，确认继续？" |
| "选手动勾选" | 立即追问 12 张清单单选 form |
| "都不做" | 礼貌结束本次会话："明白，需要时随时唤起我" |

⚠️ 数量超过 50 张时**必须**二次确认 i 豆消耗。

## Card 4 · 逐图创意确认（强制门禁）

**触发时机**：Step 3 商家确认要做的图清单后，**自动启动**。这是 R1.3 强制门禁。

**核心目的**：在烧 i 豆出图前，让商家先看一眼"AI 准备出什么样的图"，避免方向跑偏。

### 标准做法

1. 主代理切换为「创意策划师」角色
2. 基于 Step 2 洞察简报 + Step 3 选图清单，写**创意提案表**：

```
| # | 图位 | 想解决的买家疑问 | 视觉主体 | 文案方向 | 真实武器引用 |
|---|------|----------------|---------|---------|------------|
| 1 | 详情页主形象图 | "你的灯能扛沙漠高温吗？" | 沙特沙漠夜景+3 路灯 | "BUILT FOR HARSH CLIMATE" | IP67 / 25-Year Lifespan |
| 2 | SKU 矩阵 | "我能选到合适功率吗？" | 4 档功率横排+应用场景 | "FULL WATTAGE COVERAGE" | 30W/60W/100W/120W |
...（每张图都要有这一行）
```

3. 写入 `{根目录}/01_创意提案/创意提案表.md`
4. 用 ask_user form 让商家逐图选择：

### 标准 ask_user 调用（每图一个 question，最多 4 张图一组）

```
ask_user(mode="form", questions=[
  { question: "图 1 主形象图：沙漠夜景+`BUILT FOR HARSH CLIMATE`，OK 吗？", header: "图1",
    options: [
      { label: "✅ 通过", description: "直接进生成" },
      { label: "✏️ 修改", description: "下一步告诉我改哪里" },
      { label: "❌ 跳过", description: "本次不做这张" }
    ], recommended: 0 },
  ...
])
```

### 商家典型回答与应对脚本

| 商家回答 | 你必须做 |
|---------|--------|
| 全部 ✅ | 立即并行启动 R3 团队分工出图 |
| 部分 ✏️ 修改 | mode="chat" 追问："请告诉我图 X 想怎么改？"→ 修改创意提案表 → 重新出该图的卡片让商家再确认一次 |
| 部分 ❌ 跳过 | 从生成清单移除，剩余的进 R3 出图 |
| 全部 ❌ | 礼貌问："看来方向不对，要不要我调研得更深一点再重出方案？"（拉回 Step 2 重做调研） |

⚠️ **任何未通过 Card 4 的图，严禁进入 Step 4 调用 image-generation**。这条违反就是烧商家的 i 豆。

### 🔄 批量确认变体（v2.0.1 新增 · 允许 6 图整体过卡）

当待出图数量 ≥ 4 张时，逐图 ask_user form 体验疲惫。允许主代理改用「整体 3 选 1」卡片替代：

```
ask_user(mode="form", questions=[{
  question: "📋 上面是 N 张图的创意脑图表，您怎么看？",
  header: "整体方案",
  options: [
    { label: "A. 全部 ✅ 通过 — 直接出图", description: "我对所有图位的方向都满意" },
    { label: "B. 部分需要调整", description: "下一步我会用逐图卡片让您挑出要改的图" },
    { label: "C. 整体方向不对，重做调研", description: "回到 Step 2 调研更深一点再出方案" }
  ],
  recommended: 0,
  allowSkip: false
}])
```

**应对脚本**：

| 商家选择 | 你必须做 |
|---------|--------|
| A 全部通过 | 视为所有图 ✅，立即并行启动 R3 团队分工出图 |
| **B 部分调整** | **必须立即切到逐图 ask_user form**（每 4 张一组），逐图✅/✏️/❌，**不可省略** |
| C 全推翻 | 回到 Step 2 重做调研，重新出新创意提案表 |

**为什么允许整体卡？** XINTONG 回归测试发现 6 图逐图问太碎，商家"方式 A 全过"一句话就能搞定。但**B 选项后必须严守逐图**，避免商家想改图却没机会逐图反馈。

## Card 5 · 节日营销提醒（自动触发）

**触发时机**：Step 5 交付清单输出后**立即**调用 `get_time` 检查日历。

**核心目的**：跨境节日窗口期短，提前 30 天出图最有效。

### 标准做法

1. 调 `get_time` 取当前日期
2. 对照 [references/promotion-calendar.md](promotion-calendar.md) 找出 30 天内的节点
3. 如有 → 调 ask_user form：

```
ask_user(mode="form", questions=[{
  question: "🗓️ 距离 {节日名} 还有 {N} 天，要不要现在补一套促销海报？",
  header: "节日提醒",
  options: [
    { label: "好，现在做", description: "套用本次已出的图，加节日皮肤（如 EID 绿+金 / Christmas 红+绿）" },
    { label: "暂不做", description: "本次任务结束，下次再说" },
    { label: "看看节日日历", description: "我把全年节日表发您看一下" }
  ],
  recommended: 0
}])
```

### 商家典型回答与应对脚本

| 商家选择 | 你必须做 |
|---------|--------|
| 现在做 | 自动跳回 Step 3，锁定营销图第 10 项「节日促销海报」，套用本次创意继续 |
| 暂不做 | 输出最终交付总结，结束会话 |
| 看节日日历 | 把 promotion-calendar.md 关键内容用表格发出来，再问一次 |
| 当前 30 天内无节日 | **不调本卡**，直接结束会话 |

## 通用互动原则（每张卡片都适用）

1. **拒绝替商家选**：商家说"随便""你定"时，**仍要把推荐项作为 yes/no 让商家确认**（避免事后扯皮）
2. **复述确认**：所有结构化输入（路径、产品名、清单）必须复述一遍
3. **失败友好**：失败/异常时主动给降级方案，**不要让商家自己想办法**
4. **数量警告**：批量 > 50 张时强制二次确认 i 豆消耗
5. **真实性优先**：商家说"你帮我编个认证"时**必须拒绝**："抱歉，认证类信息不能 AI 编造，请确认您实际拿到的认证再告诉我"
