使用方法：把 alibaba-business-review.zip + 下面【分割线之间的整段】一起发给对方。
对方在 Accio Work 新开一个对话 → 把 zip 拖进去 → 把这段话粘贴给 AI 助手 → 等交付即可。
这段提示词已内置全部避坑规则，确保对方零配置、零冷启动，交付质量与标杆一致。

你好，我给了你一个 alibaba-business-review.zip，这是「阿里巴巴国际站 30/90 天店铺业务复盘」技能包。请严格按下面步骤执行，全程 bash，不要跳步、不要自己发挥，最终交付一份 HTML 看板 + 4 个文件。

第 0 步 · 心智校准（先读，决定质量）

本技能有 3 条铁律，违反任何一条都会让复盘作废，请你先记住：
1. 会话按子账号隔离：阿里 IM 会话只能按单个业务员账号拉。必须先查全部子账号再遍历采集，只拉主账号会漏掉 90%+ 的客户。（脚本 collect_live.py 已封装好，照用即可。）
2. 主营品类只认真实数据：店铺主营由脚本从业务员消息自动推断，严禁你从 skill 自带的案例/样例文件（cases/examples）猜测主营——那些是演示数据，跟当前店铺无关。
3. 零编造：所有数字、客户名、背调结论必须来自真实采集数据或带 source_url 的公网检索，查不到就如实标注，不许填充示例数据。

第 1 步 · 安装

unzip alibaba-business-review.zip -d /tmp/abr
cp -r /tmp/abr/alibaba-business-review ${agent_skills}/
ls ${agent_skills}/alibaba-business-review/SKILL.md   # 确认安装成功

第 2 步 · 预热（读取方法论 + 反幻觉铁律，避免冷启动）

cd ${agent_skills}/alibaba-business-review
rm -rf scripts/__pycache__ .cache 2>/dev/null
python3 scripts/preheat.py

把预热输出完整读一遍，尤其开头的「🛑 主营品类铁律」和方法论（BANT/SPIN/客户分层规则）。这一步让你具备和标杆一致的判断标准。

第 3 步 · 采集真实数据（核心，照抄命令）

cd ${agent_skills}/alibaba-business-review
python3 scripts/collect_live.py 90
  • 这个脚本会自动：查询店铺全部业务员子账号 → 遍历每个账号拉近90天会话 → 拉全消息 → 写入 data/chats.json。
  • 跑完会打印「✅ 写入 … X 有效会话 / Y 消息」。正常品牌店应有几百会话、几千条消息；如果只有个位数会话，说明子账号没拉到，检查阿里账号授权后重跑。
  • 店名可选：python3 scripts/collect_live.py 90 --shop "你的店铺名"（不填则看板显示通用名）。
  • 不要手填主营品类，step1 会自动从业务员消息推断。

第 4 步 · 跑评分 + 业务员聚焦诊断（照抄）

cd ${agent_skills}/alibaba-business-review
rm -rf scripts/__pycache__ 2>/dev/null
python3 scripts/step1_customer_scoring.py     # 客户分层（会打印自动推断的主营）
python3 scripts/step2_health_diagnosis.py     # 跟进健康度信号（含买家原话）
python3 scripts/step3_team_diagnosis.py        # 团队三维诊断
python3 scripts/step6_seller_focus.py          # ⭐业务员聚焦诊断（一人一档：核心问题+共性/个性+提升+客户行动）

第 5 步 · Top 客户公网背调（深度，接入聚焦模块）

对 step1 输出里 Tier=A/B 的重点客户做公网背调（建议 Top 12~50，越多越好）：
- 读 reports/step1_customer_scoring.json 取 A/B 档客户的 buyer_name + buyer_country。
- 分批（每批 4-5 人）并行派 browser SubAgent 做 OSINT（web_search 组合搜"姓名+国家+行业"），按 workflow/05-customer-intel.md 规范。
- 硬约束：每条结论必须带 source_url；查不到标 found:false，不编造；同名歧义要标注。
- 两个产出：
1. 汇总成 reports/top50_deep_intel.md（或 core10_customer_intel.md）——分梯队的深度背调报告。
2. ⭐ 把结构化结论整理成 reports/customer_intel.json（格式见 reports/customer_intel.example.json：buyer_name → {company,type,match,role,strategy,source}），这样背调情报会自动接进业务员聚焦模块的每个重点客户卡片。

第 6 步 · 重跑 step6 + 生成看板 + 审计

cd ${agent_skills}/alibaba-business-review
rm -rf scripts/__pycache__ 2>/dev/null
python3 scripts/step6_seller_focus.py          # 重跑：接入 customer_intel.json 背调情报
python3 scripts/step4_audit_and_dashboard.py   # 生成 HTML 看板（含业务员聚焦+背调闭环）
python3 scripts/step5_verification_csv.py      # 买家核验表 CSV
python3 audit/checklist.py --html reports/alibaba_review_dashboard.html \
  --reports-dir reports/ --chats data/chats.json --out logs/audit.json
  • 目标 P0 28/28、Verdict PASS。P1 不强制（E1 把买家原话里 "is undefined" 误报是真实原文，忽略）。
  • 若 P0 没满分：A9/A10 = 核验表/背调没生成；B 类 = 采集缺字段。回头补，不要改 skill 代码。

第 7 步 · 交付（emit 可点击链接）

把这些文件以 [名称](file:///绝对路径) 形式给我：
1. reports/alibaba_review_dashboard.html（主看板，含⭐业务员聚焦诊断模块，离线双击可开）
2. reports/top50_deep_intel.md（Top客户深度背调）
3. reports/buyer_verification_table.csv（买家核验表）
4. 「断联未激活客户挽回清单」CSV（从 step2 找含"断联未激活"信号的客户，附业务员归因）

并给我一段中文白话总结：客户分层分布、最大风险信号、团队三维短板、每个业务员的核心问题与提升重点（业务员聚焦模块的精华）、Top 高价值客户。
